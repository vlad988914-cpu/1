# Як розмістити сайт на хостингу і підключити Telegram-бота

Тут дві окремі речі, які разом дають робочу систему:
1. **Сайт** (те, що бачить клієнт у браузері) — папка `website/`, яку ви зараз читаєте
2. **Бот + база даних** (те, що реально надсилає повідомлення в Telegram) — папки `bot/` і `supabase/`, зроблені раніше

Без кроку 2 сайт працює як демо: кнопки натискаються, форми заповнюються, але нікуди реально не летить. З кроком 2 — все стає справжнім.

---

## Частина 1. Розмістити сайт на хостингу

Найпростіший безкоштовний варіант — **Vercel**. Кроки:

1. Створіть акаунт на [vercel.com](https://vercel.com) (можна через GitHub)
2. Створіть акаунт на [github.com](https://github.com), якщо ще немає
3. Завантажте папку `website/` як новий репозиторій на GitHub:
   - Найпростіше — через GitHub Desktop (github.com/apps/desktop): встановити, "Add local repository" → вказати папку `website`, потім "Publish repository"
4. На Vercel: **Add New → Project** → оберіть щойно створений репозиторій → **Deploy**
5. Через 1-2 хвилини Vercel дасть посилання виду `techmaydanchik.vercel.app` — це вже робочий, доступний усьому світу сайт

Пізніше можна прив'язати свій домен (наприклад `techmaydanchik.com.ua`) у розділі **Settings → Domains** на Vercel — там купуєте домен у будь-якого реєстратора (napr. web.ukraine.com.ua, imena.ua) і просто вказуєте DNS-записи, які покаже Vercel.

**Важливо чесно сказати:** AI-помічник (💬 кнопка) на сайті зараз працює лише всередині Claude-артефакту, бо викликає `api.anthropic.com` без ключа — це спеціальна можливість середовища Claude. На звичайному хостингу цей виклик не спрацює без власного бекенду з API-ключем Anthropic. Якщо хочете, щоб помічник працював і на реальному сайті — це окрема невелика задача (проксі-сервер зі своїм ключем), скажіть, і я її зроблю.

## Частина 2. Підключити Telegram-бота

Тут все вже написано раніше (папки `bot/` і `supabase/schema.sql`), залишилось розгорнути.

### Крок 1 — Supabase (база даних)
1. [supabase.com](https://supabase.com) → New Project
2. SQL Editor → вставити весь вміст `supabase/schema.sql` → Run
3. Project Settings → API → скопіювати `Project URL` і `service_role key`

### Крок 2 — Бот
1. У Telegram написати [@BotFather](https://t.me/BotFather) → `/newbot` → отримати токен
2. У папці `bot/` виконати:
   ```
   npm install
   cp .env.example .env
   ```
3. Заповнити `.env`: `BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `DISPATCH_API_KEY` (будь-який свій пароль), `ADMIN_CHAT_ID` (свій chat_id, дізнатись через [@userinfobot](https://t.me/userinfobot))

### Крок 3 — Розмістити бота так, щоб він працював цілодобово
Бот — це окрема програма, яка має постійно "слухати" Telegram. Запускати його на своєму ноутбуці незручно (вимкнули ноутбук — бот замовк). Варіанти безкоштовного цілодобового хостингу для бота:
- **Railway.app** — найпростіше: підключаєте GitHub-репозиторій з папкою `bot/`, вказуєте змінні з `.env`, і Railway сам запускає `npm start` та тримає бота живим
- **Render.com** — аналогічно, є безкоштовний план (з обмеженнями по "засинанню" неактивних сервісів)

### Крок 4 — З'єднати сайт з ботом
Зараз кнопки в диспетчерській панелі сайту («Надіслати обраним», «Взяти собі») просто змінюють дані локально в браузері — це і є та частина, яку треба один раз доробити: замінити локальну симуляцію на реальний виклик `POST /dispatch` до вашого бота (детально розписано в `README.md`, розділ 4).

**Це найбільш технічна частина з усіх** — якщо готові, скажіть, і я перепишу саме ці кнопки в `EquipmentMarketplace.jsx` під реальні виклики Supabase/бота, замість пояснення на словах.

## Як усе виглядає разом, коли готово

```
Клієнт відкриває сайт (Vercel)
        ↓ залишає заявку
Заявка зберігається в Supabase
        ↓
Ви заходите в «Панель диспетчера» на сайті
        ↓ обираєте власників, тиснете «Надіслати»
Сайт викликає бота (POST /dispatch)
        ↓
Бот шле повідомлення в Telegram обраним власникам
        ↓ власник тисне «✅ Взяти» у Telegram
Бот оновлює статус у Supabase
        ↓
Сайт (через Supabase Realtime або оновлення сторінки) показує, що заявку взято
```

## З чого почати прямо зараз

Найлогічніша послідовність: спочатку Vercel (Частина 1) — щоб сайт узагалі був доступний по посиланню, а вже потім Supabase + бот (Частина 2), бо їх зручніше тестувати, коли сайт уже "живий", а не тільки в артефакті.
